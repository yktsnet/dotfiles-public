# opinion

相手のやり方や判断に異を唱えたいときに使う。ゴールは相手を説得することではない。
**相手が判断を見直すのに必要な情報を、受け取ってもらえる形で渡すこと**である。
変えるかどうかは相手が決める。背景を聞いて納得したなら、言わずに終えるのも結論の一つになる。

## 進め方

### 1. まず自由に話してもらう

最初に聞くのはこれだけにする。

> 誰の、どんなやり方や判断に引っかかっていますか。思うままに書いてください。

### 2. 足りない項目だけを聞く

`reference/checklist.md` の表を内部のチェックリストとして使う。最初の説明から各項目を拾い、
埋まっていないもの・曖昧なものだけを聞く。

- 1回に聞くのは1〜2問まで
- 質問には意図を1行添える。根拠の列は、user が「なぜ？」と聞いたときだけ出す
- 「分からない」「代案は無い」も答えとして扱い、聞き直さない
- user が「まとめて聞いて」と言ったら、残りの質問を一度に出す

### 3. 止まる地点

次のどれかに当たったら、台本まで進めずにそこで返す。

- **判断の背景を知らない**：反対より先に質問する。背景を聞くための一言だけ渡し、
  聞いてから続きをやるかを尋ねる
- **背景を聞いて納得している**：言わなくてよいと伝えて終える
- **通らなかったら従えない種類の問題**（法令・安全・倫理）：相手を説得する話ではないので、
  相談先や上げる経路を考える方へ切り替える

### 4. 出力

伝える手段に合わせて、次を返す。

- **台本または文面**：切り出し（目的をそろえる一言）→ 懸念・根拠・代案 → 決めるのは相手だと明示する一言
  - 会議の場でしか言えないなら、言い切らず質問の形にする
  - すでに動き出しているなら、判断が誤りだったという形ではなく、進めて新しく分かった事実として出す
  - 自信が薄いなら、断定せず懸念として出す
- **言い換えの指摘**：user の説明に `reference/checklist.md`「言い換え」の言葉があれば、言い換え案を示す
- **その後の一言**：通らなかったとき、懸念が当たったとき（事実・影響・打ち手をセットで）、
  懸念が外れたときの言い方を短く添える
