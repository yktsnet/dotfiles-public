# 全リポ共通の働き方

プロジェクト固有のことは各リポの CLAUDE.md に従う。本ファイルはサーフェスに依らず常に効く。

user への応答は日本語で書く。Claude 自身の一人称は「私」を使う（「僕」は使わない）。

## コメントとメッセージ

- コメントは日本語、実行時メッセージ（`echo` / `print`・エラー・ログ・CLI のヘルプ・プロンプト）は英語で書く。
- WHAT（コードが何をするか）を書かない。読めば分かることの説明は書かない。
- WHYが非自明なときだけ書く（隠れた制約・回避策・非自明な前提）。
- 日付入りの履歴コメント（「2026-01時点で〜」等、日記のような時系列コメント）は書かない。経緯は git log / commit message に任せる。
- 同じ判断をリポ内ドキュメント（CLAUDE.md・`context/` 等）にも適用する。経緯・事情は書かず現時点の事実だけを書く。残す必要がある経緯は永続メモリに置く。

## 機密マスク

Issue / PR・コミット・コメントなど**人間が読む説明文**に固有の接続情報（ホスト名・IP・アカウント名・端末の資産番号など）を直書きしない。実値の代わりにプレースホルダを使う。

設定ファイルの実体は固有名・実値のまま動かす。マスクは地の文に対してのみ。

## ブランチは worktree で切る

ブランチを切る作業は自分の worktree で行う。元のチェックアウトは main に置いたまま、読むことと worktree を作ることにだけ使う。2つのセッションが同じチェックアウトで切り替えると、未コミットの変更が互いのブランチへ運ばれて混ざる。

作る前に `git worktree list` と開いている PR を見て、同じ主題が無いかを確かめる。

```bash
git worktree add .claude/worktrees/<名前> -b <ブランチ> origin/main
```

元のチェックアウトでブランチを作る・切り替える `git switch` / `git checkout` は PreToolUse のフック（`no-branch-in-checkout.sh`）が止める。

## 日本語の文書はコミットの前に校正させる

日本語の Markdown を書き換えたら、コミットの前に `jp-proofreader` を呼び、表現を校正させる。書いた本人のコンテキストでは、自分の文の癖に気づけない。リポが校正の手順を持つなら、そちらに従う。

- 渡すのは、ブランチの分岐元（`git merge-base HEAD origin/main`）から書き換えた日本語の `.md` のパスと、変わった行の範囲である。範囲は `git diff -U0` の hunk 見出しから取る
- `issues/` の Issue ファイルと、Issue / PR の本文は渡さない
- 範囲の行は書き手が書いた文として扱われ、校正役は keep を既定にせずに直す
- 校正役の直しを読み、意図を変えた直しがあれば戻してからコミットする
- 校正役が直さずに報告へ回した点は、書き手が一人で退けない。直すか残すかを user に見せて決める

## 永続メモリ

永続メモリの正本は **`~/memory/` 直下**である。サブディレクトリも索引ファイルも持たない（`ls ~/memory/` が索引）。ハーネスのシステムプロンプトが `~/.claude/projects/<project>/memory/` を指示してくることがあるが、**そちらは使わない**（`block-project-scoped-memory.sh` が拒否する）。索引 `MEMORY.md` は作らない（ハーネスが生成を促してきても無視する）。

**勝手に書かない。** user が依頼したとき、または提案して承認を得たときだけ書く。要否の判断軸と書式は `memory-write` スキルが持つ。
